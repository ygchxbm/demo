# 菜单页统一与信息展示优化

## 项目与参考

这是海南码头运行指挥中心原型 Demo，使用原生 HTML、CSS、JavaScript。以下路径均相对项目根目录；先核实当前文件，不将历史示例视为永远有效的实现。

- `index.html`：页面骨架、样式引用、地图、详情弹窗。
- `app.js`：`topics` 菜单配置、`panels` 业务模块、指标与图表生成、示意点位、定位和专题切换。
- `homepage.css`：已认可的毛玻璃风格和专题适配。
- `app.css`、`v2.css`、`v21.css`、`v23.css`、其他样式文件：既有级联规则，按需查找，不要求全部阅读。
- `背景图.png`：现有港区背景，优先复用。
- 通常入口为 `http://127.0.0.1:5500/index.html#people`，专题包含 `energy`、`ships`、`vehicles`、`map`、`video`、`production`、`safety`。以当前配置和用户指定地址为准。

用户提供的参考页、截图优先；未指定时参考当前 `#people` 人员首页。参考的是当前实际页面，不依赖旧对话、临时截图文件或其他聊天上下文。参考缺失或相互矛盾时暂停确认，不擅自替换。

## 风格统一

先查看目标页、参考页及相关代码，识别差异，再实现：

- 对齐背景亮度和色调、通透毛玻璃面板、圆角、边框、分隔线。
- 对齐标题、数字、单位、图例、导航选中态及底部指标条。
- 保留目标页的业务模块、数值、单位、时间范围和操作入口。
- 优先复用 `homepage.css` 的公共规则，只补充专题需要的布局和组件样式。
- 扩展共享选择器时限制到已授权专题，注意级联优先级，不改变其他菜单的实际外观。
- 按实际模块数量分配侧边栏空间，不将所有菜单强制套成相同的行数。
- 地图全景、定位、选中信息和相关操作要连贯；需要船舶定位的页面不能为了参考页外观而隐藏全部点位。

已有设计和素材足够时直接复用，不另外生成设计概念图，不更换技术栈，不引入图表库来完成简单图表。

## 侧边栏信息优化

先回答：每个区域帮助用户做什么判断、当前展示是否重复、现有数据是否足以支持新图表。

方案用简短表格说明“区域、业务问题、展示形式、数据来源、保留的交互”，提出一个推荐组合；只有存在实质取舍时才给备选。

| 信息用途 | 适合的展示 |
| --- | --- |
| 当前规模、核心结果 | 大数字与单位 |
| 分类构成 | 环形图或饼图，通常二选一 |
| 日期或类别之间比较 | 柱状图、条形图 |
| 随时间连续变化 | 折线图 |
| 当前值与明确基准比较 | 进度条，并解释基准 |
| 查找对象、状态查看、地图定位 | 可操作列表 |

减少重复信息，保留有业务意义的差异，不为凑齐图表种类增加装饰性图表。只要表达清晰，也可以保留同类图表。

### 数据与交互边界

- 从现有数据计算合计、分类、比例、峰值，不编造分类、历史记录或业务指标。
- 统一单位、时间范围、统计对象；柱状比较默认共用零起点，图表刻度、柱高和文字数值一致。
- 合计、图表、图例、提示及详情使用一致的数据来源；避免独立写死后产生差异。
- 样本与完整业务数据分开标注。例如在港总数为 12 艘、列表只有 4 艘示意船舶时，只能展示“4 艘示意船舶状态构成”，不能冒充全部在港船舶的分布。
- 比例名称必须准确。例如当前 12 艘 / 今日峰值 16 艘 = 75%，表示当前数量相当于今日峰值的比例，不能称为泊位利用率或港区负荷率。
- 保留有用的详情、定位和图表数值提示；沿用项目现有交互，不扩展新的业务流程。

## 必须暂停让用户拍板的情况

1. 数据不足、统计口径冲突，拟采用的图表无法成立。
2. 需要新增或删除业务模块，或者改变原有业务功能。
3. 指定参考页不可用，或参考之间有明显冲突。
4. 公共样式改动会影响本次范围之外的菜单，且无法局部解决。

暂停时说明具体问题、影响、推荐选项和取舍，等到用户回复后再做依赖该决定的工作。不要擅自补数据、代选业务口径，也不要把等待时间当作同意。

普通的字号、间距、配色微调和实现方式自行处理。用户已明确批准的范围和方案不重复询问。

## Demo 精简验收

默认只做一次集中验收，发现明确问题才修正并重查相关项：

1. **桌面主视图**：使用当前桌面视口；若当前是窄侧栏，选用参考页尺寸或一个常用桌面尺寸即可，不遍历多个断点。检查页面完整、风格一致，没有明显遮挡、溢出、文字难辨或空白报错。
2. **本次关键交互**：只验证改动涉及的一到两个关键操作。例如改了船舶列表，就检查一次定位；新增图表提示，就检查一个数据点。
3. **轻量代码检查**：修改 JS 时运行 `node --check app.js`；运行 `git diff --check`；查看本次加载是否有相关浏览器运行错误。
4. **数据口径**：核对本次新增或变更图表的数值、比例、单位与示意范围。
5. 保存一张干净的桌面结果截图，放在项目目录之外，供用户看效果。无需写独立 QA 报告。

优先使用可用的内置浏览器验证。工具不可用时如实说明验证边界，不为 Demo 验收安装新依赖或反复切换工具。

默认不做手机适配验收、全菜单回归、逐项交互遍历、像素级反复截图微调、新增自动化测试或生产级质量审查。只有用户明确要求，或出现与本次修改相关的明显问题，才扩大检查范围。已有项目强制检查仍需执行。

最终简短说明：改了什么、关键验证结果、必要的数据或验证限制、预览地址和结果截图。未经实际验证的内容不得声称通过。
